# 4. Детальная спецификация компонентов

## 4.1. Иерархическая рабочая память

Рабочая память организована в три уровня:

```
Уровень 1: ФОКУС (Focus)
- Последние 3-5 событий с максимальной важностью
- Определяет текущую "тему" мышления

Уровень 2: АКТИВНЫЙ КОНТЕКСТ (Active Context)
- События, связанные с текущей целью (по тегам или семантически)
- До 20 элементов

Уровень 3: ФОН (Background)
- Все остальные события, не вошедшие в Top-K
- Хранятся для быстрого доступа, но не в контексте
```

**Каждый элемент содержит:**

```typescript
interface WorkingMemoryItem {
  id: string;
  type: 'user_message' | 'observer_thought' | 'executor_utterance' |
        'drive_event' | 'memory_result' | 'mcp_result' | 'reality_check';
  content: any;
  timestamp: number;
  importance: number;        // 0-10, динамически пересчитывается
  source: string;
  tags: string[];
  emotionAtTime?: EmotionVector;
  goalId?: string;
  reflectionDepth?: number;  // для отслеживания глубины диалога
  embedding?: number[];      // опционально, для семантического поиска
}
```

**Механизмы:**

| Механизм | Описание |
|----------|----------|
| **Добавление** | Новый элемент помещается в Фокус, сдвигая старые. Важность присваивается сенсорным препроцессором |
| **Забывание** | Элементы с важностью ниже порога или старше `maxAge` удаляются из Фона |
| **Привыкание (habituation)** | Если элемент повторяется, его важность снижается |
| **Устаревание (decay)** | Каждые N тиков важность умножается на `exp(-age / halfLife)` |
| **Усиление контекстом** | Если событие семантически близко к цели, важность временно повышается |
| **Выбор контекста** | Для промптов: Focus + до N из Active + при необходимости из Background |

## 4.2. Система драйверов (потребностей)

### 4.2.1. Пять базовых потребностей

| № | Потребность | Полярность | Описание |
|---|-------------|------------|----------|
| 1 | **Исследование / Любопытство** | Центробежная | Потребность в новой информации, данных, опыте |
| 2 | **Безопасность / Целостность** | Центростремительная | Защита от сбоев, ошибок, вредоносных воздействий |
| 3 | **Социальность / Взаимодействие** | Центробежная | Потребность в общении, помощи, кооперации |
| 4 | **Достижение / Компетентность** | Центробежная | Успешное выполнение задач, повышение мастерства |
| 5 | **Когнитивный комфорт / Энергосбережение** | Центростремительная | Минимизация сложности, избегание перегрузки |

### 4.2.2. Полярность драйверов

- **Центробежные** (экспансивные): исследование, социальность, достижение
- **Центростремительные** (сохраняющие): безопасность, когнитивный комфорт

**Конфигурация драйвера:**

```typescript
interface DriverConfig {
  id: 'curiosity' | 'safety' | 'social' | 'achievement' | 'comfort';
  baseLevel: number;           // 0-1
  decayRate: number;           // увеличение в секунду
  thresholdLow: number;        // порог для лёгкого беспокойства (0.3)
  thresholdHigh: number;       // порог для критической потребности (0.8)
  polarity: 'centrifugal' | 'centripetal';
  influence: {                  // влияние на эмоции
    valenceDelta: number;        // изменение валентности за единицу уровня
    arousalDelta: number;        // изменение возбуждения
  };
  satisfactionAction?: string;  // действие, удовлетворяющее потребность
}
```

## 4.3. Эмоциональная система (Valence–Arousal–Dominance)

Используем трёхмерную модель эмоций:

| Ось | Диапазон | Описание |
|-----|----------|----------|
| **Valence** | -1..1 | Приятно/неприятно |
| **Arousal** | 0..1 | Возбуждение/спокойствие |
| **Dominance** | 0..1 | Контроль/подчинение |

**Правила обновления** конфигурируются через JSON:

```json
{
  "eventType": "user_message",
  "valenceDelta": 0.2,
  "arousalDelta": 0.1,
  "condition": "event.sentiment === 'positive'"
}
```

**Буферизация:** резкие изменения сглаживаются скользящим средним (окно 3-5 событий).

### 4.3.1. Функциональная карта эмоций (причинно-следственная цепочка)

Эмоции не влияют на параметры LLM напрямую. Вместо этого изменение эмоционального вектора модифицирует **веса соответствующих драйверов**, что через рефлексию Наблюдателя приводит к корректировке параметров генерации.

**Процесс для оси Arousal (возбуждение):**
1. Событие повышает Arousal
2. Высокий Arousal увеличивает вес драйвера «исследование/любопытство`
3. Драйвер генерирует `drive_event` в рабочую память
4. Наблюдатель формулирует мысль о поиске новых подходов
5. Исполнитель может повысить `temperature` для креативности

**Аналогичные цепочки:**
- **Низкая Valence** → драйвер безопасности → Наблюдатель замечает угрозу → Исполнитель повышает `repetition_penalty`
- **Высокая Dominance** → драйвер достижения → Наблюдатель отмечает уверенность → Исполнитель расширяет `top_p` и `max_tokens`

## 4.4. Долговременная память

Три типа памяти:

| Тип | Содержание | Механизм хранения |
|-----|-----------|-------------------|
| **Эпизодическая** | События с контекстом (время, эмоции) | Векторная БД (LanceDB) + эмбеддинги |
| **Семантическая** | Факты о себе и мире | Ключ-значение + эмбеддинги |
| **Процедурная** | Привычки, навыки | JSON + счётчики выполнения |

**Важность** пересчитывается динамически:
```
importance = baseImportance * (1 + 0.1 * accessCount) * emotionFactor - age * decayRate
```

### 4.4.1. Семантическая компрессия

Периодически (например, каждые 1000 циклов) группа семантически близких воспоминаний объединяется в одно сжатое воспоминание.

```typescript
interface CompressedMemory {
  id: string;
  type: 'compressed';
  originalIds: string[];
  summary: string;               // обобщение (генерируется LLM)
  timeRange: { from: number; to: number };
  averageImportance: number;
  centroidEmbedding: number[];
  tags: string[];
}
```

### 4.4.2. Защита от потери важных уроков

Перед компрессией система проверяет, связаны ли воспоминания с событиями, получившими **сильное отрицательное подкрепление** (`outcome = -1`). Такие воспоминания:
- Не сжимаются
- Помечаются флагом `priority_review`
- Передаются мета-когнитивному модулю для анализа

## 4.5. Механизм привычек и обучения

### 4.5.1. Формирование и использование привычек

**Привычка** — закреплённый паттерн «ситуация → действие». Привычки предлагаются Исполнителю как кандидаты, но окончательное решение остаётся за ним.

**Процесс:**
1. **Менеджер привычек** хранит привычки с полями: `triggerPattern`, `action`, `strength`, `outcomeBuffer`
2. Перед каждым тактом ищутся привычки, подходящие под текущий контекст (по эмбеддингам)
3. Найденные привычки передаются в промпт Исполнителя как подсказки
4. Исполнитель может: выбрать привычку, проигнорировать или модифицировать её
5. После выполнения механизм подкрепления обновляет силу привычки
6. При `strength > autoExecuteThreshold` (например, 0.95) действие выполняется автоматически без LLM

### 4.5.2. Обучение с подкреплением и учёт долгосрочных целей

**Базовая формула:**
```
Δstrength = learningRate * (outcome - expectedOutcome) * (1 - uncertainty)
```

**С учётом долгосрочных целей:**
```
Δstrength_final = Δstrength * (1 + β * goalAlignment)   если outcome >= 0
Δstrength_final = Δstrength                              если outcome = -1
```

Где `goalAlignment` — косинусное сходство эмбеддинга действия с долгосрочными целями.

## 4.6. MCP-интегратор

Обеспечивает доступ к внешним инструментам через Model Context Protocol.

**Формат вызова:**
```
[MCP_CALL] {
  "server": "filesystem",
  "tool": "read_file",
  "args": { "path": "/project/src/main.ts" }
}
```

Результат возвращается как событие `mcp_result` в рабочую память.

## 4.7. Сенсорный якорь (Reality Check)

Каждый N-ный тик (конфигурируется) в рабочую память добавляется событие проверки реальности:

```json
{
  "type": "reality_check",
  "content": "Проверка связи с реальностью. Есть ли новые внешние сигналы?",
  "importance": 8
}
```

Наблюдатель обязан отреагировать, что предотвращает зацикливание на внутренних состояниях.

## 4.8. Мета-когнитивный модуль рефлексии

**Функции:**
- Мониторинг паттернов поведения за последние N циклов
- Обнаружение ригидности: если Исполнитель consistently выбирает один паттерн при отрицательном подкреплении → `rigidity_detected`
- Инициация рефлексивного диалога высокого приоритета
- Анализ приоритетных воспоминаний и формирование уроков

---

## 4.9. Метрики когнитивного здоровья

| Метрика | Описание | Способ вычисления |
|--------|----------|-------------------|
| Коэффициент успешности | Доля успешных действий за период | Программно, скользящее среднее |
| Когерентность диалога | Среднее косинусное сходство между последовательными мыслями | Программно (эмбеддинги) |
| Интеграция памяти | Доля успешных обращений к LTM | Программно |
| Индекс ригидности | Количество циклов без смены паттерна при неудачах | Программно |
| Энтропия рабочей памяти | Разнообразие типов событий | Программно |

---

## 4.10. Когнитивный гомеостаз и индекс дрейфа личности

**Мета-драйвер самосохранения** отслеживает метрики здоровья и при выходе за пределы инициирует вмешательства.

**Индекс дрейфа личности** (расчёт раз в 1000 циклов):
1. Собираются эмбеддинги всех действий Исполнителя за период (подвыборка до 100)
2. Вычисляется центроид — вектор текущего поведения
3. Сравнивается с **эталонным вектором архетипа** (усреднённый эмбеддинг `longTermGoals`)
4. Косинусное расстояние даёт дрейф (0 = совпадение, 1 = противоположность)
5. При дрейфе > 0.3 генерируется `personality_drift` (приоритет 9)

**Таблица вмешательств:**

| Уровень | Симптомы | Действие |
|---------|----------|----------|
| Зелёный | Норма | Мониторинг |
| Жёлтый | Успешность < 0.4 или валентность < -0.3 | Генерация `mild_drive_event` |
| Оранжевый | Успешность < 0.2 И валентность < -0.5 ИЛИ дрейф > 0.3 | Принудительный рефлексивный диалог |
| Красный | Индекс ригидности > предела | Мягкий сброс (температура, консолидация, любопытство) |

## 4.11. Ценностный вектор (этический компас)

```json
"valueVector": {
  "benevolence": 0.8,
  "integrity": 0.7,
  "curiosity": 0.9,
  "security": 0.4,
  "cooperation": 0.6
}
```

При принятии решения Наблюдатель оценивает соответствие действия вектору ценностей. Действия с низким сходством получают отрицательное подкрепление.

## 4.12. Сенсорный препроцессор (Input Processor)

Модуль обрабатывает входящие сигналы **до** попадания в рабочую память. Все операции **без вызова LLM**.

**Функции:**

| Функция | Описание |
|---------|----------|
| **Извлечение базовых признаков** | Длина, знаки вопроса/вослицания, смайлики, имена собственные, ключевые слова |
| **Вычисление важности** | Формула: `base + lengthFactor + nameBonus + questionBonus + sentimentScore + goalSimilarityBoost` |
| **Базовая тональность** | Лёгкий классификатор: `'positive'`, `'neutral'`, `'negative'` |
| **Извлечение сущностей** | Имена, географические названия, термины — по словарям и правилам |
| **Вычисление эмбеддинга** | Быстрый энкодер (sentence transformer) для семантического поиска |
| **Сравнение с целью** | Косинусное сходство с эмбеддингом активной цели для `goalSimilarityBoost` |
